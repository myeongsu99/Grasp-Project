## 1. 로봇 조립 — SO-101 + AmazingHand

- **팔**: SO-101, Feetech STS3215 서보 5개(어깨 회전·어깨·팔꿈치·손목 굽힘·손목 회전), 포트 COM9, 1 Mbaud.
- **손**: Pollen AmazingHand, SCS 계열 서보 8개(손가락 4개 × 2), 포트 COM8. 팔과 손은 **서로 다른 통신 규격**(프로토콜 0 / 1)이라
  한 프로세스에서 같이 쓸 때 서로 통신을 깨뜨리는 문제를 찾아 해결했습니다(`robot/robot_control.py`의 `_sync_end`).
- **결합 확인**: 손을 손목 롤 서보에 장착한 상태에서 팔 5관절 + 손 8서보를 한 프로그램에서 동시에 구동해 파지 동작을 수행했습니다(§3, §4).
- **시뮬레이션 모델**: 같은 구성을 MuJoCo에 만들었습니다(공식 AmazingHand CAD 메시 사용, `docs/evidence/figures/rl_hand_model.png`).
- **부족한 증빙**: 조립 과정·완성 사진/영상은 저장소에 없어 **별도 촬영이 필요**합니다.

## 2. Calibration

### 2-1. 카메라 (체커보드)
| 항목 | 결과 |
|---|---|
| 내부 파라미터 재투영 오차 | **0.27 px** (26장, 나쁜 11장 자동 제외) |
| 초점 거리 / 주점 | fx 994, fy 989 px / (708, 406) |
| 왜곡 | k1 −0.43, k2 +0.21 (배럴) |
| 외부 파라미터 재투영 오차 | **0.22 px** |
| 검증 (모서리 30개 복원) | 20 mm 격자를 **평균 0.08 mm, 최대 0.20 mm** 오차로 복원 |

그림: `figures/undistort_check.png`, `figures/extrinsic_check.png` · 파라미터 파일: `pretrained/cam.json`

### 2-2. 카메라 → 팔 (hand-eye, 픽셀 → 관절각)
책상 위 한 점의 **픽셀 (u, v)를 팔 관절각 5개로 바로** 바꾸는 2차 다항식을 데이터로 맞췄습니다
(렌즈 왜곡·카메라 자세·책상 평면·팔 기구학을 식 하나가 흡수).

| 항목 | 결과 |
|---|---|
| 수집 | 30점 중 이상치 8점 제외 → **22점** (같은 팀 A팀 수집, 파일: `robot/calib/handeye_teammate.json`) |
| 관절 오차 (leave-one-out) | **평균 1.23°** (관절별 0.77~1.54°) |
| 손끝 위치 오차 (안 본 자리) | **평균 12 mm**, 90%가 23 mm 이내 |
| 유효 범위 | 20.9 × 11.4 cm |

- 우리 팀이 한 수집은 처음에 **29.6° 오차**로 실패했습니다(손으로 끌다 손목이 15° 흔들림). 원인을 찾아 로봇이 격자를 돌며
  책상 접촉을 감지하는 **자동 수집**(`robot/calib/auto_collect.py`)과 **손 피치 일정 모델**(lift + elbow + wrist_flex ≈ 166°)을 만들었습니다.
- 두 팀의 각도 기준이 서로 달라(서보 내부 영점) **팀원 기준으로 통일**했고, 시뮬레이션 ↔ 실물 관절 대응표(손목 위치 평균 3.0 mm 일치)도 구했습니다.

## 3. 관절 움직임 테스트

| 항목 | 결과 | 증빙 |
|---|---|---|
| 팔 4관절 (pan, lift, elbow, wrist_flex) | 캘리브레이션 값으로 이동·하강·복귀를 **15회 파지 시도**에서 수행 | `logs/trials_*.csv`, `logs/auto_*.csv` |
| 손 4손가락 | 폄·`pinch`·`power`·벌림(`power_splay`) 자세 구동, 4손가락 모두 동작(약지는 가동 폭 약 80%) | `robot/hand_splay_test.py` |
| 관절 한계 | 관절별 실측 소프트 리밋 적용 | `robot/robot_control.py` |
| 안전장치 | 손끝 25 mm 띄우기(책상 누름 방지), 확인 창, 전체 종료 키, 중단 후 자동 복귀 | `robot/team_fk.py`, `robot/recover.py` |
| **손목 회전(wrist_roll)** | 켜면 어깨·손목 서보가 같이 응답을 끊는 증상이 있었고 **원인 미확정**. 기본으로 켜도록 설정을 바꿨으나 **아직 실물에서 확인하지 못함** | `HANDOFF.md` §3 |

- 손목 회전이 없으면 물체를 **한 방향으로만** 잡을 수 있어서, 이 제약이 실물 성공률에 영향을 준 것으로 보입니다.

| 손 방향 | `pinch` → `power` | 첫 성공 |

- 표본이 작고(15회), 가운데 놓인 캔은 성공했지만 상자 가장자리는 실패가 많았습니다. 아직 **통계적으로 믿을 수준의 수치는 아닙니다.**
- 시도별 기록: `logs/*.csv`

## 5. Physical AI 학습

### 5-1. 비전 모델 학습
- GR-ConvNet을 Cornell 885장으로 학습(RGB만), 중단 시 자동 재개, 5-fold 교차검증(§4-1).
- **팀원이 촬영한 103장으로 파인튜닝**을 시도했으나 IoU가 0.21을 넘지 못해 **실패**했습니다(원인은 라벨 형식 문제로 추정, 미해결). 배포 모델은 Cornell 학습본입니다.

### 5-2. 강화학습 (MuJoCo 접촉 물리)
- **환경**: SO-101 + 손가락 힘이 전달되는 AmazingHand(공식 메시와 링크 움직임을 측정해 재구성) + **355 ml 캔**(66 × 122 mm), 서 있는 캔 / 누운 캔 50:50.
- **방법**: 스크립트 파지 위에 정책이 보정만 더하는 **잔차 PPO**, 병렬 환경 14개, 600만 스텝.
- **결과** (잡음 없는 평가):

| | 스크립트만 | 학습된 정책 |
|---|---|---|
| 서 있는 캔 (80회) | 42% | **79%** |
| 누운 캔 (40회) | 100% | **100%** |

그림: `fig_rl_training.png`(학습 곡선), `figures/rl_portfolio.gif`(동작) · 로그: `logs/rl_final_progress.csv` · 모델: `pretrained/ppo_can/`

- **시행착오**: 처음부터 학습한 1차 시도는 105만 스텝까지 성공 0%(캔에 닿기만 하고 쥐지 않음) → 잔차 방식으로 전환. 2차 시도는 성공 시 종료하는 보상을 정책이
  악용(6 cm 아래에서 버팀)해 보상은 오르고 성공률은 떨어짐 → 보상 구조 수정.

### 5-3. 아직 안 된 것
- **학습된 정책의 실물 적용은 못 했습니다.** 시뮬레이션과 실물의 관절 대응표는 완성했지만(§2), 실물 파지 자세(손을 테이블 높이에 수평으로 눕힘)가
  시뮬레이션의 위에서 내려잡기와 달라 그대로 옮기면 캔이 들리지 않았습니다(288회 중 2회). 실물 파지 순간의 사진으로 손-캔 배치를 확인한 뒤 시뮬레이션을 맞춰 재학습할 계획입니다.

## 다시 확인하는 방법
```bash
git clone https://github.com/vpfmtldk/Grasp-Project.git && cd Grasp-Project
pip install -r requirements.txt
python predict_grasp.py --network pretrained/grconvnet_rgb/weights.pt --image <사진>
python -m robot.rl.eval_policy --model pretrained/ppo_can --view --mode mixed     # 학습된 정책 재생
```
